# 对话输入框显示灰色预测句，按 Tab（手机上点一下）补全

## 想要什么
## 目标

首页「Talk to God」对话卡的输入框加上类似 Cursor 的行内补全：预测的文字用浅灰色显示在输入框里、紧跟在光标后面，桌面端按 Tab 采纳，手机上点灰字采纳。补全有两个来源：

1. **AI 猜下一句**：每条普通回复（非设计会话）结束时，模型顺带写一句猜访客接下来最可能说的话。输入框为空时，这句就以灰字显示。不多发模型请求：这句话是同一条回复的一部分。
2. **边打字边补全**：输入框里有字时，用已打出的文字去匹配候选句的开头，把剩下的部分用灰字接在后面。候选句依次是：AI 这次猜的那句、首页示例问题（`GOD_CHAT_PRESETS` 的 `text`）、访客在这个浏览器保存的会话里发过的话（从 `chatArchive` 里取各会话的 user 消息，新的在前、去重，不包括以 `/` 开头的命令）。不经过 AI，打字时立刻出现。

## 后端（workers/ai）

- 在 `workers/ai/src/chat/prompts.ts` 的 `basePrompt` 里加一段规则：每条回复最后另起一行，写一个语言标记为 `next` 的代码块，里面只有一行：用访客的语言、以访客口吻写的下一句可能的提问，长度不超过共享常量规定的上限。不要在其他地方提到它；拒答，或者要调用 `start_design` 的回复不写。语言标记和长度上限从新的共享模块导入，不要在提示词里另写一份。
- 设计会话的规划者提示词不改，规划者的回复不带预测。
- `workers/ai/src/chat/reply-fences.ts` 的图示校验本来就不管非图示语言，这里只需在 `workers/ai/src/reply-fences.test.ts` 补一例，确认 `next` 块不会被记成无效图示。
- 预测块是回复正文的一部分，照常进入签章历史和对话记录，不新增 NDJSON 事件，也不改请求和响应契约。

## 共享模块

新建 `shared/god-chat-next.ts`，导出：
- `GOD_CHAT_NEXT_FENCE = "next"` 和 `GOD_CHAT_NEXT_MAX_CHARS`（取 80 左右）；
- `splitNextSuggestion(content: string): { body: string; next?: string }`：只认回复**末尾**的 `next` 块（包括流式输出中还没收尾的半截块），返回去掉这个块后的正文和这句预测（取第一行，去掉首尾空白；为空或超长就不要）。不在末尾的 `next` 块不处理。
配套测试 `shared/god-chat-next.test.mts`：覆盖完整块、没收尾的块、没有块、超长、多行、块不在末尾这几种情况。

## 浏览器

- `src/components/god-chat/message-parts.tsx#ReplyBody`：渲染前先用 `splitNextSuggestion` 去掉末尾的预测块，流式输出时和打开旧会话时都去掉。卡片的插入位置超过正文长度时，按正文末尾算。预测句不显示在气泡里。
- 新建 `src/lib/chat-completion.ts`：一个纯函数，输入当前草稿和候选列表，返回要补上的剩余文字。草稿为空时返回 AI 那句；草稿以 `/` 开头时不补全，让命令面板优先；匹配时忽略大小写和全半角差异（NFKC），候选句必须比草稿长；采纳后保留候选句原来的写法。配套测试 `src/lib/chat-completion.test.mts`。
- 新建 `src/components/god-chat/completion.tsx`，放灰字叠层和相关逻辑，让 `src/components/god-chat.tsx`（已超过 20 KB）只接线、不再变大：
  - 叠层与 textarea 字体、内边距、换行规则完全一致，放在输入框文字下方或上方，草稿部分透明，补全部分用 `text-muted-foreground`，深浅色模式自动适配，`aria-hidden`。
  - 只在光标位于末尾、没有选中文字、不在输入法组字（`isComposing`）、没在等回复、人机验证没有占用输入框、命令面板没打开时显示。显示 AI 预测时隐藏 placeholder。
  - 只在精确指针设备（`pointer: fine`）上，在灰字末尾加一个小的 `Tab` 键标识（界面文案用英文）；触屏上不显示这个标识。
  - **Tab**：有补全时阻止默认行为，把补全并入草稿，光标移到末尾；没有补全时 Tab 保持浏览器默认行为（切换焦点），不影响键盘导航。命令面板打开时仍按现有逻辑处理。
  - **Esc**：先收起当前补全，再输入时重新计算。
  - **触屏和鼠标点击**：灰色补全部分可以点（其余叠层不拦截点击），点一下就采纳，并让输入框保持焦点、光标在末尾。手机上只用这种方式采纳，不加额外按钮。
  - AI 预测只取当前会话最后一条助手回复，并且只在回复完成后取。发送新消息、`/new` 或切换会话时，换成对应会话的数据。
- `src/components/god-chat.tsx`：接入上面的组件和 Tab、Esc 处理，候选列表由示例问题、本地历史和 AI 预测组成。

## 不做

- 不在每次按键时调用 AI，也不新增接口或额度。
- 不改隐私说明的去向：预测由同一家模型在同一条回复里写出，没有新的数据去向。

## 验收标准
- [ ] 发一条普通消息，回复完成后输入框为空并显示一句灰色预测；回复气泡里看不到 next 代码块，流式输出时也不会闪出来；打开旧会话也一样。
- [ ] 桌面端有灰色补全时按 Tab，补全并入输入框、光标在末尾；没有补全时按 Tab 照常切换焦点；输入以 / 开头时命令面板照旧，不出现灰字。
- [ ] 输入「LYJW 现」时补全成「LYJW 现在在忙什么？」，输入自己以前在这个浏览器问过的话的开头也能补全；按 Esc 收起补全。
- [ ] 375px 手机宽度（含 WebKit）下灰字和输入的文字对齐，不错位也不溢出；不显示 Tab 标识；点灰字就采纳，输入框保持焦点。
- [ ] 浅色和深色模式下灰字都看得清；中文输入法组字时不显示灰字，Tab 不会打断组字；等待回复和人机验证期间不显示灰字。
- [ ] shared/god-chat-next.test.mts、src/lib/chat-completion.test.mts 和 workers/ai/src/reply-fences.test.ts 新增的用例通过，ai Worker 的类型检查与测试通过。
