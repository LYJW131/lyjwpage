# 让首页聊天框可以附一张图片一起发送

## 想要什么
## 目标

首页 “Talk to God” 聊天卡片的输入框支持给消息附一张图片。模型能看到图片，并结合图片回答。

## 访客能看到的行为

- 输入框左侧（发送按钮所在那一行）新增一个附图按钮，用 lucide 图标（如 `ImagePlus`），样式照 Stop 按钮那样做成次要按钮，`aria-label="Attach image"`。点按钮会打开系统选图，只接受 `image/jpeg`、`image/png`、`image/webp`、`image/gif`。
- 也可以在输入框里粘贴图片，或把图片拖到输入区。
- 选好图片后，输入框上方显示一张小缩略图，右上角有移除按钮（`aria-label="Remove image"`）。每条消息最多一张图，再选一张会替换掉前一张。
- 只有图片、没有文字时也能发送：发送按钮在“有文字或有图片”时可用。纯图片消息的正文用共享常量里一段固定的英文占位文字（例如 `[Image]`）。
- 访客发出的气泡里，文字上方显示这张图片的缩略图。图片只留在当前页面内存里。刷新页面或从存档打开旧会话时，那条消息改为显示一个小标签 `Image`（`label-mono` 风格），不显示图片。
- 设计会话（规划者接手）期间隐藏附图按钮，忽略粘贴和拖入的图片。
- 出错时把图片留在输入区，在现有的错误提示行显示英文提示，例如：文件格式不支持、图片太大、图片读取失败。
- 所有界面文字用英文，颜色、间距、圆角照 `DESIGN.md` 和现有输入框的写法，在 375px 手机宽度和深色模式下都要正常显示。

## 图片处理（浏览器端）

- 新建 `src/lib/chat-image.ts`：用 canvas 把图片按比例缩到长边不超过 1568px，重新编码为 JPEG（GIF 取第一帧），得到 base64。重新编码后，EXIF 里的定位等元数据会一起去掉。
- 编码后的字节数超过共享上限（例如 `GOD_CHAT_IMAGE_LIMITS.maxBytes`，取 1.5 MB）时，降低质量再试一次，仍然超限就报错，不发送。
- 请求体里只给**最后一条访客消息**附 `image: { mediaType, data }`。更早的消息不再带图片。

## 协议与 Worker

- `shared/god-chat.ts`：新增 `GOD_CHAT_IMAGE_LIMITS`（允许的格式、最大字节数）和纯图片消息的占位文字常量。`GodChatRequest` 增加可选的 `image` 字段（只属于最后一条访客消息）。`parseGodChatRequest` 要校验：格式在白名单内、data 是合法 base64、解码后不超过上限、带了 `designToken` 或 `resume` 时一律拒绝。原有的历史签章格式不变，图片不进签章。
- `workers/ai/src/chat/handler.ts`：请求体上限随图片上限调高，留出 base64 膨胀和历史文字的余量。图片只交给 Anthropic 模型：在 `toModelMessages` 生成的最后一条 user 消息里，文字之前插入一个 `image` 内容块（base64 source）。Clef 路由和配额照旧只看文字。系统提示里补一句：访客可能附图片，图片只在附图那一轮可见。
- `workers/ai/src/chat/history.ts`：支持给最后一条访客消息附上图片块，生成的前缀和缓存行为保持不变。
- 不能把图片数据、请求正文写进任何日志或错误消息。

## 存档

- `src/lib/chat-archive.ts`：`ChatBubble` 增加可选标记 `image?: true`，`validBubble` 接受这个标记。存档只存标记，不存图片数据。缩略图另外保存在组件内存里，以消息 id 为键。

## 文档

- `workers/ai/README.md`「首页对话」：说明图片附件的范围（只在当轮可见、不进历史签章、不存档、设计会话不支持），上限以共享常量为准。

## 测试

- `workers/ai/src/god-chat.test.ts`：覆盖 `parseGodChatRequest` 接受合法图片，拒绝超限、格式不支持、base64 非法的图片，以及和 designToken、resume 同时出现的情况。
- `workers/ai/src/god-chat-handler.test.ts`：带图片的请求发给 Anthropic 时，最后一条 user 消息里有 image 块；下一轮历史里没有图片。
- `src/lib/chat-archive.test.mts`：带 `image: true` 的气泡能通过校验、存取后保留下来，存档里没有图片数据。

## 验收标准
- [ ] 桌面和 375px 手机宽度下，输入框旁都有附图按钮；用按钮选图、粘贴图片、拖入图片都能附上，并显示可以移除的缩略图
- [ ] 发送一张图片和一个问题后，回复明确提到了图片内容；只发图片、不写文字也能发送并得到回复
- [ ] 超过大小上限或格式不支持的图片不会发出，输入区显示英文错误提示，图片仍留在输入区
- [ ] 刷新页面后，旧会话里那条消息显示 Image 标签、不显示图片，存档里没有图片数据；后续对话照常进行
- [ ] 设计会话期间没有附图按钮；Worker 拒绝同时带图片和设计会话令牌的请求
- [ ] pnpm --dir workers/ai test 和主站 pnpm test 通过，新测试覆盖了图片校验、模型消息里的 image 块和存档标记
- [ ] 深色模式下缩略图、按钮和 Image 标签的颜色与现有输入框一致，控制台没有报错
