# lyjw.me 运行原理 · 画面升级本子（v2：全片 2D）

> 类型：reference

这份本子定下一版讲解动画的概念、风格、分镜结构和技术路线，先审本子再写代码。事实一律出自 [FACTS.md](FACTS.md)，本子里提到的机制都能在那里找到出处。章节表、逐段画面和逐句旁白在 [SCRIPT.md](SCRIPT.md)，写章的契约在 [v2/CONVENTIONS.md](v2/CONVENTIONS.md)。

用户看过第 02、03 章样章后拍板**全篇统一 2D**：第 02 章的纸面检查单是全片的标杆，第 03 章是暗底平面图加白卡详图（见下文 03 节）。

参考：[mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)。借它的方法：

- 画面是时间的纯函数。
- 本子先行。
- 一条贯穿全片的母题。
- 每章一种视觉语言，但共用同一套调色板和字体。
- 硬切落在强拍上。
- 字就是画面的一部分，不是贴在上面的字幕。

不借它的：歌词对齐流程（我们的配乐是自己合成的，节拍天生已知）；离线渲 mp4（交付仍是可播放的 HTML）。

## 一句话概念

**一封信封的旅程，画成一本工程图册。** 代码里本来就管两样东西叫「信封」：上报器发出的遥测，和首屏里每张卡片的数据。片子跟着一封信封（Mac 上的一次换歌），从它在 Mac 上被写出来，一路走到访客屏幕上那张卡片翻面。每一章是图册里的一页「图版」，各用一种工具和画法：

- 野外仪器的专利图
- 公文和印章
- 只有一间屋子的账房
- 活字印版
- 电报示波器
- 地铁线路图
- 节拍器
- 心电图和地层

整本图册共用同一张纸、同一种墨、同一种橙色。

## 母题

1. **信封（贯穿全片的「火花」）**：一个 Claude 橙的亮点，拖着一根发丝线。镜头推近时，它是一个极小的信封（矩形加 V 形封舌）。它的一生：
   - 在 Mac 上被写出来
   - 在入口被拆开、分成四路
   - 在账房里排队
   - 被印进首屏
   - 顺着电报线送到浏览器
   - 在地图上跑两条线
   - 最后在回顾章一口气走完全程
2. **四个库，四种符号**，全片一致（共用 `K.glyph`，第 02 章的管子底下、第 03 章的对照表都是它）：
   - 实时层：DO，一间屋子
   - 可滞后层：KV `LAG`，一墙带时间签的格子
   - 历史：D1，一条望不到头的档案架，长期保存
   - 凭据：KV `CREDENTIALS`，一只带锁的小抽屉

   观众看到符号就知道数据落在哪一层。
3. **钥匙与门**：每把钥匙只开权限表上写着的门（Home Assistant 那一把开两扇）。第 02 章立起来，回顾章再出现一次。
4. **两只钟**：服务器的钟，和访客浏览器自己的钟。在线判断、可滞后卡取数、播放进度，都是「浏览器按自己的钟算」。这个母题在第 05 章立起来。
5. **Clawd**：像素螃蟹，片子的脸。出场规则见「已定」。

## 调色板

取自站点 `globals.css` 的 token，实现时按 oklch 换算成线性色：

| 名 | 来源 token | 用途 |
|---|---|---|
| ink | 暗色 `--background` oklch(0.15 0.008 85) | 暗图版底色 |
| ink2 | 暗色 `--surface` oklch(0.185 0.008 85) | 面板、暗底上的实心物件 |
| paper | 亮色 `--background` oklch(0.94 0.007 92) | 纸面图版底色、暗底上的白卡 |
| bone | 暗色 `--foreground` oklch(0.93 0.012 90) | 暗底上的字与线 |
| graphite / ash | `--muted-foreground` 两档 | 次要线、注记（纸上用 graphite，暗底用 ash） |
| **signal** | `--claude` oklch(0.672 0.131 38.8)；暗底用 oklch(0.74 0.115 39) | 信封、强调、橙色印章。全片唯一发光的颜色 |
| ember | signal 提亮 | 信封亮核 |
| **live**（稀有） | 暗色 `--live` oklch(0.76 0.16 148)；纸面用亮色 oklch(0.65 0.17 145) | 只属于「在线」这一个含义：第 05 章在线人数、第 08 章的可用格。别处不用 |

规则：

- 暗图版和纸面图版交替，形成明暗节奏。橙色在两种底上都还是橙色。
- 只有 signal / ember 可以超过发光阈值，bone 字不发光。
- 不用别的色相。站点卡片里本来的颜色（活动圆环三色、各品牌色）在片中都画成 signal / bone。

## 字体

| 字体 | 声部 |
|---|---|
| Geist（Medium / SemiBold / Bold） | 标题、英文旁白 |
| Geist Mono | 机器的声音：端点、状态码、JSON、计时、注记 |
| Geist Pixel | Clawd、终端、章节号 |
| PingFang SC（系统字，回退 Noto Sans SC） | 中文旁白与标注 |

排版：

- 瑞士网格、不对称构图、大量留白、发丝细线。大字旁边配小号 Mono 注记。
- 不描边、不加光晕。
- **手机可读性下限**：舞台按 1920×1080 逻辑像素排版，375px 宽的手机上会缩到约 0.2 倍。
  - 旁白不小于 56 逻辑 px（手机上约 11px）。
  - 要读的标注不小于 28 px。镜头拉远时按缩放折算：缩放 0.66 下，世界坐标里的字要写到 46 px 以上。
  - 更小的字只能当纹理，不能承载信息。

## 语气与禁区

- 一直有东西在动，大变化落在拍子上：强拍硬切，鼓点上盖章、落卡、翻面。强缓动，停住后再猛地弹出，不做飘来飘去的屏保式运动。
- 精确而不花哨：发丝线、高反差字、克制的颜色。冷面幽默：一本正经的脚注、印章、状态码。
- 不做 AI 味：
  - 不要紫青霓虹、发光大脑、代码雨、粒子星云、镜头光晕堆叠。
  - 不要云朵图标加服务器机柜这类库存图示。
  - 厂商只以 Mono 字出现名字，不画厂商 logo，不模仿别家产品界面。站点自己的主页可以画。

**不上画面**（沿用上一版的口径）：

- 窗口标题的隐私判断：只说 Jev 参与、拿不准交主人、放行才进信封。不写判据、阈值、例子。示意概率条不和出路对应。
- Sentry：不出组织名、监控 ID、真实报错标题、可用率数字。令牌只画成一张卡，不出名字；它的权限范围未核（FACTS §8），不说「只读」。
- 不出真实密钥和 token 的 client id，钥匙只画成「mac 的钥匙」。
- 歌词用占位。
- 延迟数字要重测过才能出现；上一版的 8 月实测作废。

## 2D 画法总则

全片每一页都是一张平面图版，下面这些做法各章通用（第 02、03 章已经验证过）：

- **图版底**：纸面（`K.PLATE.paper`：纸纹、纤维、墨点、40 / 200 的图纸网格）和暗底（`K.PLATE.ink`：墨色底、很淡的云纹、骨白网格）两种，都是按世界坐标画的全屏 2D 着色器，镜头动时纸纹跟着纸走。
- **镜头**：只有平移、缩放、旋转。一章一张大图纸，分几个机位；镜头在强拍上甩到下一个机位（约 0.2–0.3 小节，`E.io`），停住时慢慢推 1–3%。甩镜头带运动模糊，冲进、拉出带径向模糊，都是按镜头速度算的后期。
- **物件**：一律正视或俯视（专利图、平面图、立面图），不画透视。门开是门扇平着变窄；卡片翻面是纵向压扁再弹开；「从地里升起」是往上平移、裁到地平线以上。
- **详图**：暗底图版上要读的文字放进白卡（`K.sheet`，按纸片模式合成，和纸面图版是同一张纸）。白卡用虚线圈加虚线引到画面里的实物上，这是工程图的「详图」画法。纸面图版上直接写。
- **旁白**：大字（≥ 56 px），逐字亮起，排在每个机位留好的位置上（多在左下），和图一起构图。
- **打勾、印章、灯**：清单按拍打勾（`K.checkbox`），印章落在强拍上（`stamp` 合成模式），「等齐几样才放行」画成一排灯。
- **发光**：只有 signal 色的东西进发光层（信封亮核、灯、广播的环），其余都不发光。

### 00 这张卡片从哪来

1. 开场接续上一版：终端 `$ claude`，Clawd 蹦出来（交接）。
2. 站点主页用发丝线在纸面上画出来。镜头推到「正在听」那张卡，歌名刚好翻面，一个橙点落在卡上。
3. 标题：「这张卡片，是怎么知道的？」
4. 镜头顺着橙点身后那根线往回拉，拉出总览图：采集 → 中枢 → 展示。中枢分成三块（入口 ingress、状态核心 api、采集 collector），下面挂着四个库的符号。

**2D 画法**：暗底终端用 Geist Pixel 字和闪烁光标。主页是正视的平面线框（不透视），卡片按首屏真实布局的比例排；翻面是纵向压扁再弹开。拉远是纯缩放，总览图三栏、四个库符号用 `K.glyph`。

### 01 野外观测站（FACTS §1）

镜头横移，经过六件仪器，每件画成暗底上的专利图：

- 笔记本（Mac）
- 手机（iPhone，由 HealthKit 唤醒来报圆环和训练）
- 家里：HomePod 和 PS5 的电源开关（Home Assistant），旁边是 n100 上的 PlayStation 容器，在同一个局域网里探测主机醒没醒
- NAS 机箱（Emby）
- 东京的机柜，上面两台容器（服务器、编码账号）
- 云端的一小段遥测（Claude Code OTLP）

最后是一只**表盘**：collector，每分钟一响，每个任务一根指针，各走各的节奏。

Mac 这一站展开讲：

- 信封 `{version:4, presence, heartbeatAt, activeModules, modules}` 在旁边用 Mono 敲出来，只有变了的模块亮起。
- 没变化时每 90 秒寄一个空信封，画成一次呼吸。
- 切应用先等 400 ms 落定，画一把小尺子。
- 窗口标题先过 Jev：几道问题的条纹同时转，同一刻一起给出概率条。放行的进信封，拿不准的弹给主人。
- 图片：像素压成一条哈希 `sha256….png`，直接落进 R2 的抽屉。信封里只剩一个文件名。

**2D 画法**：一长条暗底图纸，镜头只做横移（每件仪器一个机位，强拍上甩）。仪器是正视专利图：骨白发丝线、编号引线（FIG. 1…）、剖切斜线。信封 JSON 放进白卡详图逐字敲出。呼吸是一个圆环缩放；400 ms 是一把平面刻度尺；Jev 的几道问题是并排横条同时走；表盘是正视钟面。

### 02 门禁与分拣（FACTS §2）

图版翻成**纸面**，墨线加橙色印章。这一章已经做完，是全片的标杆。

1. **一墙八扇门**：每封上报带着自己的钥匙卡，Emby 的钥匙去开 mac 的门，被 403 印章盖回去。
2. **一张检查单**，按代码顺序逐项打勾：
   1. POST
   2. 来源认识
   3. Access 凭证（RS256，aud / iss / exp）
   4. 秤上称重：不超过 4 MiB
   5. 是 JSON
   6. prepare

   不通过的项各飞一枚章：不是 POST 盖 405，来源不认识盖 404，凭证盖 401 / 403（验不了时 503），超重和不是 JSON 盖 400，prepare 失败盖 400（状态核心还没准备好时盖 503）。OTLP 那一路另有一枚 415，这里不画。
3. **分拣台**：信封拆开，内容分进四根气动管：实时、可滞后、归档、凭据。
   - 服务器的信封整封不进状态核心：它的管子分叉到可滞后格子和档案架。冷面脚注：「服务器：整封不进屋。」
4. **202 这枚章要等三盏灯**：DO、LAG、凭据。D1 那盏不等，它在后台慢慢亮。
5. 旁注：改检查单只需要重新发布入口，屋里的灯不闪，连接不断。

**2D 画法**：一张 3840×2160 的纸面图纸分四格（门墙、检查单、分拣台、三盏灯），镜头在强拍上甩到下一格，最后拉远看整张图纸，再冲进「状态核心」那盏灯，整屏化成橙色落黑，接第 03 章。门扇开合是平着变窄，不做透视。

### 03 一间屋子的账房（FACTS §3）

**暗底平面图 + 白卡详图**：空间用一张俯视的建筑平面图交代，含义交给白卡详图（第 02 章检查单的做法）。一张暗底图纸，三个机位，镜头只在强拍上甩：

- **A 屋里**：左边一路进口（上报入口）排成一条队，栏杆立柱拉绳，只有一条队。中间是一间屋子的平面图：墙体剖切打斜线，左墙门洞（门扇开到 90°，四分之一圆弧是它扫过的地方），一张桌、一把椅子（同一时刻只有一个人在记）、一盏灯、一本摊开的账本，右墙一道缝。右栏两张白卡详图：账本、「要做的事」。
- **B 门外**：墙缝外的 StateCore 岗亭、LivePushRoom 的天线、所有开着的页面；回执飞回画面左边的入口。
- **C 拉远**：屋子缩成一个图形，另外三个库从地平线升起，右边一张「四个库」对照表。

逐拍画面、旁白和配乐锚点见 [SCRIPT.md](SCRIPT.md) 第 03 章；配乐在 `v2/music/ch03.js`。

事实口径（34eb555 复核）：切应用只推 `desktop`、不失效首屏，所以主角用「换歌」这封，不用切应用；DO 只交回 `event / listening / tags` 三种要做的事，StateCore 用 `waitUntil` 在后台照办，所以回执不等广播；202 由入口在写完 LAG 和凭据后才盖，屋里不画 202。

### 04 活字印版（FACTS §4）

**纸面印刷**：主页是一块块印版拼成的一页，每张卡一块，各自缓存。

- 访客来了，从存货里递出一张印好的页。
- 一个标签失效：只有那一块印版重铸，旧页照发，新页在后台印。
- 没挂标签的那几块印版，只看 600 秒的定时器。
- 某个来源 5xx：那块印版不动，继续用上一份。

**2D 画法**：纸面，俯视一整页首屏：印版按首屏真实布局的比例排成网格，每块写卡名（≥ 28 px）。标签失效时那一块被夹起（往上平移、投影变深，不做 3D 翻转）、按 `stamp` 模式重新印上、放回；同时出纸口照旧递出旧页。没挂标签的印版角上各一个 600 秒的圆形计时环。5xx 那块盖一枚「沿用上一份」章。块数按写章时的代码数，旁白里不说数（见 SCRIPT.md 第 04 章）。

### 05 电报线（FACTS §5）

**暗底示波器**，横轴是时间：

1. HTML 还在解析，head 里的小脚本就开始接电报线 `/ws?visible=1`，收到的电报先放进一只小托盘。
2. 等页面 hydrate 完，`useLiveEvents` 接过线，托盘里的电报按顺序重放。时间轴只画先后，不标毫秒数（没重测过）。
3. 一条推送到：写进 SWR，卡片当场翻面。
4. 一个慢回来的旧轮询带着更早的时间戳，被弹开。
5. 播放进度条按「位置 + (现在 − 观测时间)」自己往前走，歌词占位逐字亮。
6. **两只钟**：卡片的在线点到了截止时间、源站什么也没说，它照样自己熄灭，因为浏览器按自己的钟判断。
7. 同一根线数两种人：开着的页面，和正在看的页面。切后台只发一个 `hidden`，线不断。这里第一次出现 live 绿。
8. 一张「预期到货表」：可滞后卡在 `updatedAt + 节奏 + 15 秒` 时才去取；推送连着时，在听列表、在看、在玩、奖杯这几张退成 5 分钟兜底。

**2D 画法**：暗底，一条 signal 色的示波曲线横贯画面（发光层）。小托盘是一叠小卡片，hydrate 是一道竖刻线；卡片翻面同第 00 章。旧轮询是一只小信封撞上时间戳闸门弹开。进度公式用 Mono 写在进度条旁边。两只钟是两个正视钟面（服务器、访客浏览器）。预期到货表是一张白卡表格。

  3. 两个域名的 `/api/version` 都答出新版
  4. 入口收到 site-deployed
  5. 广播 version
  6. 所有开着的页面顶上弹出 UPDATE 卡

### 07 节拍器（FACTS §7）

**纸面上三台节拍器**：PlayStation（n100 上的容器）、编码账号限额（agents-reporter）、服务器（server-reporter），各按一种依据定节奏：

- PS 看局域网里的主机醒没醒（发现包），不问人数：醒着走快档，休息或关机走闲档。醒着和没醒一对调就立刻打一轮，开机不用等满闲档；休息和关机来回切不额外打；退避没到时一律不放行。
- 限额看人数：有人正看 → 快；只开在后台 → 中；没人 → 慢（5 / 10 / 60 分钟）。人数问不到就当 0：只会变慢，不会变快。
- 服务器固定每 60 秒敲一下，不问人数。它是对照：闲时每分钟问一次人数，本身就不比直接推一次省。
- 入夜主机进休息、访客走光：PS 落到闲档，限额那台打 12 个 5 分钟的盹，只有服务器那台照旧。
- 配乐在这一章真的换档：全速、半速、很慢，再回到全速（逐段见 SCRIPT 第 07 章）。

**2D 画法**：三台正视节拍器（梯形机身、摆杆绕支点转），摆速跟着配乐换档。推送房间画成第 03、05 章那根天线（`K.glyph("room")` 的小屋是「实时 · StateHub」，这里不用），旁边一张人数表（`online` 正在看、`connections` 开着的，Mono 数字）；只有限额那一台连过去问 `GET /count`，PS 那一台连向家里的主机、一路发发现包。小盹画成摆杆停住、头顶一串 z。

### 08 心电图与地层（FACTS §3、§8）

**暗底**，两个方向相反的信号：

- Sentry 每分钟来敲一次门（HEAD `/api/version`）。
- Worker 每 5 分钟去报到。冷面脚注：「报到只证明 cron 跑完了。」

collector 每 5 分钟取回结果，LYJWPAGE 卡上 30 天一天一格，今天那一格亮一下（live 绿第二次、也是最后一次出现）。

然后镜头往下沉，进入**地层**：

- pulse 每分钟归档进 D1。
- Coding 每 15 分钟一窗，交给 Jev 打分。全是零的窗不问 Jev，直接记最低档。打分只在屋里（StateHub）放 7 天，不进 D1。
- 分钟 cron 每分钟往地层右沿压进一薄片，长期保存。

Clawd 收尾：「线上出错时，我先来这儿查证据。」

**2D 画法**：两个信号画在同一条心电图横线上：向内的尖峰是 Sentry 敲门，向外的是 Worker 报到。30 天格子是一张白卡。「下沉」是镜头纵向平移，地层是一层层水平色带（墨色深浅），右沿是此刻，每拍压进一薄片，越往左越早。Coding 的窗是横向一格一格，全零的格直接落最低档；Jev 打出的档画成窗里的一根横线，旁注它不进 D1。

**2D 画法**：一张横向长图版，把前面各章缩成一格格并排，镜头沿信封的路一路平移，强拍上推近；信封进哪一格，那一格就换回那一章的底（纸面 / 暗底）亮一下。各章的画法要能以函数形式复用（见下文「Phase 2」的共享约定）。

## 技术路线

- **位置**：`docs/explainer/v2/`，发布前一直是独立目录，不进站点构建；替换线上时再改 `scripts/build-explainer.mjs`（按内容哈希发布，脚本和音频经 `window.__assets` 查名字）。
- **引擎：保留 v2 自写的 WebGL2 引擎，只当 2D 合成器用。** 决定的理由：第 02 章（标杆）的质感来自纸纹、墨吃进纸、橡皮章空隙这几种逐像素的合成和后期（只让 signal 起泛光、颗粒、暗角、按镜头速度的运动模糊），换成纯 Canvas2D 要么丢掉这些、要么在 CPU 上逐像素重做；而 2D 用法下它已经很轻（实测见下）。
  - 没有光线步进、透视相机，也没有 3D → 屏幕的投影。
  - 镜头：`{x, y, zoom, rot}` 四个数，Canvas2D 图层（`Layer.cam`）和着色器（`uCam`）用同一套；关键帧用 `K.keys`，`K.camera(CAM, b, BAR)` 顺带给出运动模糊和径向模糊。
  - 图版底：`K.PLATE.paper` / `K.PLATE.ink`，`uPlate` 限定网格范围。
  - 合成模式：`normal`、`add`（只给 signal 的发光）、`ink`（纸上吃墨；暗底上的骨白线也用它）、`stamp`（橡皮章）、`paper`（暗底图版上的白卡，颜色乘同一套纸纹）。
  - 图层共用：各章按名字从 `G.layer(name, scale)` 取（`ink`、`paper`、`stamp`、`top`、`emit`@0.5），同一时刻只画一章，所以十章共用一组画布；着色器用 `G.pass(src)` 按源码缓存。
  - 共用件在 `kit.js`：`glyph`（四个库）、`sheet`（白卡）、`checkbox`、`leader`（引线标注）、`pathAt / pathLen / trailOn`、`camera`，以及原有的文字、信封、印章、Clawd、气泡、火花。
- **确定性**：画面只取决于时间 t。随机数一律带种子，逐帧闪烁按帧号算。`?export`、`?t=`、`window.__ready`、`__seek`、`__duration`、`__chapters`、`__BAR` 保持不变。
- **双语**：所有文字在源头按句查表（`I18N.tr(key)`，中英两列）：播放器的字在 `v2/i18n.js`，各章的字在各自文件顶部的 `I18N.add`。时长仍按中文算，两种语言共用一条配乐；英文句子要按画面位置控制长度（多为两行）。
- **性能**（Apple Silicon，无头 Chrome + Metal，`__seek` 含 `gl.finish()`，整帧时间）：
  - 1920×1080：第 02 章中位 2.6 ms、p90 4.2 ms；第 03 章中位 1.8 ms、p90 3.7 ms。
  - 3840×2160（DPR 2 的 1080p 屏）：中位 4–5 ms、p90 7–11 ms；第 03 章拉远后偶有一帧约 68 ms，疑为大白卡的阴影模糊在 4K 下贵，Phase 2 查。
  - 375 px 宽 × DPR 3（画布 1125×633）：中位不到 1 ms。
  - 真机手机没测。竖屏手机按 16:9 加黑边显示。没有 WebGL2 的浏览器要不要退回 Canvas2D 直出（没有纸纹和后期），Phase 2 定。
- **播放器**：去掉配乐选择，其余保留（播放 / 暂停、拖动、语言切换、封面、重播、触屏底栏）。样章的播放器是最小版，Phase 2 补齐。
- **自检**：`v2/tools/check.mjs` 中英各把一章逐帧画一遍，报太小的字、缺文字键和报错；`v2/tools/stills.mjs` 按章节小节抽帧（`--lang en` 出英文、`--scale 0.2` 出 375px 手机等效图），无头 Chrome 截画布；不要用浏览器面板截图（面板隐藏时是空帧）。联系表用 ImageMagick `montage` 拼。流程见 CONVENTIONS「自检」。
