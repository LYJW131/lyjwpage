# lyjw.me 运行原理 · 画面升级本子（草案 v1）

这份本子定下一版讲解动画的概念、风格、分镜结构和技术路线，先审本子再写代码。事实一律出自 [FACTS.md](FACTS.md)（按 main eb429ed 核对），本子里提到的机制都能在那里找到出处。旁白逐句写在本子通过之后的 SCRIPT.md 里。

参考：[mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)。借它的方法：

- 画面是时间的纯函数。
- 本子先行。
- 一条贯穿全片的母题。
- 每章一种视觉语言，但共用同一套调色板和字体。
- 硬切落在强拍上。
- 字就是画面的一部分，不是贴在上面的字幕。

不借它的：歌词对齐流程（我们的配乐是自己合成的，节拍天生已知）；离线渲 mp4（交付仍是可播放的 HTML）。

## 一句话概念

**一封信封的旅程，画成一本工程图册。** 代码里本来就管两样东西叫「信封」：上报器发出的遥测，和首屏里每张卡片的数据。片子跟着一封信封，从它在 Mac 上被写出来，一路走到访客屏幕上那张卡片翻面。每一章是图册里的一页「图版」，各用一种工具和画法：

- 野外仪器的专利图
- 公文和印章
- 只有一间屋子的账房
- 活字印版
- 电报示波器
- 地铁线路图
- 节拍器
- 心电图和地层

整本图册共用同一张纸、同一种墨、同一种橙色。

## 母题

1. **信封（贯穿全片的「火花」）**：一个 Claude 橙的亮点，拖着一根发丝线。镜头推近时，它是一个极小的信封（矩形加 V 形封舌）。它的一生：
   - 在 Mac 上被写出来
   - 在入口被拆开、分成四路
   - 在账房里排队
   - 被印进首屏
   - 顺着电报线送到浏览器
   - 在地图上跑两条线
   - 最后在回顾章一口气走完全程
2. **四个库，四种符号**，全片一致：
   - 实时层：DO，一间屋子
   - 可滞后层：KV `LAG`，一墙带时间签的格子
   - 历史：D1，一条望不到头的档案架，长期保存
   - 凭据：KV `CREDENTIALS`，一只带锁的小抽屉
   
   观众看到符号就知道数据落在哪一层。
3. **钥匙与门**：每把钥匙只开权限表上写着的门（Home Assistant 那一把开两扇）。第 02 章立起来，回顾章再出现一次。
4. **两只钟**：服务器的钟，和访客浏览器自己的钟。在线判断、可滞后卡取数、播放进度，都是「浏览器按自己的钟算」。这个母题在第 05 章立起来。
5. **Clawd**：像素螃蟹，讲解员，见下面「待你拍板」。

## 调色板

取自站点 `globals.css` 的 token，实现时按 oklch 换算成线性色：

| 名 | 来源 token | 用途 |
|---|---|---|
| ink | 暗色 `--background` oklch(0.15 0.008 85) | 暗图版底色 |
| ink2 | 暗色 `--surface` oklch(0.185 0.008 85) | 面板 |
| paper | 亮色 `--background` oklch(0.94 0.007 92) | 纸面图版底色 |
| bone | 暗色 `--foreground` oklch(0.93 0.012 90) | 暗底上的字与线 |
| graphite / ash | `--muted-foreground` 两档 | 次要线、注记 |
| **signal** | `--claude` oklch(0.672 0.131 38.8)；暗底用 oklch(0.74 0.115 39) | 信封、强调、橙色印章。全片唯一发光的颜色 |
| ember | signal 提亮 | 信封亮核 |
| **live**（稀有） | 暗色 `--live` oklch(0.76 0.16 148)；纸面用亮色 oklch(0.65 0.17 145) | 只属于「在线」这一个含义：第 05 章在线人数、第 08 章的可用格。别处不用 |

规则：

- 暗图版和纸面图版交替，形成明暗节奏。橙色在两种底上都还是橙色。
- 只有 signal / ember 可以超过发光阈值，bone 字不发光。
- 不用别的色相。站点卡片里本来的颜色（活动圆环三色、各品牌色）在片中都画成 signal / bone。

## 字体

| 字体 | 声部 |
|---|---|
| Geist（Medium / SemiBold / Bold） | 标题、英文旁白 |
| Geist Mono | 机器的声音：端点、状态码、JSON、计时、注记 |
| Geist Pixel | Clawd、终端、章节号 |
| PingFang SC（系统字，回退 Noto Sans SC） | 中文旁白与标注 |

排版：

- 瑞士网格、不对称构图、大量留白、发丝细线。大字旁边配小号 Mono 注记。
- 不描边、不加光晕。
- **手机可读性下限**：舞台按 1920×1080 逻辑像素排版，375px 宽的手机上会缩到约 0.2 倍。
  - 旁白不小于 56 逻辑 px（手机上约 11px）。
  - 要读的标注不小于 28 px。
  - 更小的字只能当纹理，不能承载信息。

## 语气与禁区

- 一直有东西在动，大变化落在拍子上：强拍硬切，鼓点上盖章、落卡、翻面。强缓动，停住后再猛地弹出，不做飘来飘去的屏保式运动。
- 精确而不花哨：发丝线、高反差字、克制的颜色。冷面幽默：一本正经的脚注、印章、状态码。
- 不做 AI 味：
  - 不要紫青霓虹、发光大脑、代码雨、粒子星云、镜头光晕堆叠。
  - 不要云朵图标加服务器机柜这类库存图示。
  - 厂商只以 Mono 字出现名字，不画厂商 logo，不模仿别家产品界面。站点自己的主页可以画。

**不上画面**（沿用上一版的口径）：

- 窗口标题的隐私判断：只说 Jev 参与、拿不准交主人、放行才进信封。不写判据、阈值、例子。示意概率条不和出路对应。
- Sentry：不出组织名、监控 ID、真实报错标题、可用率数字。令牌只说「只读」。
- 不出真实密钥和 token 的 client id，钥匙只画成「mac 的钥匙」。
- 歌词用占位。
- 延迟数字要重测过才能出现；上一版的 8 月实测作废。

### 00 这张卡片从哪来

1. 开场接续上一版：终端 `$ claude`，Clawd 蹦出来。
2. 站点主页用发丝线在纸面上画出来。镜头推到「正在听」那张卡，歌名刚好翻面，一个橙点落在卡上。
3. 标题：「这张卡片，是怎么知道的？」
4. 镜头顺着橙点身后那根线往回拉，拉出总览图：采集 → 中枢 → 展示。中枢分成三块（入口 ingress、状态核心 api、采集 collector），下面挂着四个库的符号。

### 01 野外观测站（FACTS §1）

镜头横移，经过六件仪器，每件画成暗底上的专利图：

- 笔记本（Mac）
- 手机（iPhone，由 HealthKit 唤醒来报圆环和训练）
- 客厅里的 HomePod 和 PS5 电源开关（Home Assistant）
- NAS 机箱（Emby）
- 东京的机柜，上面两台容器（服务器、编码账号）
- 云端的一小段遥测（Claude Code OTLP）

最后是一只**表盘**：collector，每分钟一响，11 根指针各走各的节奏。

Mac 这一站展开讲：

- 信封 `{version:4, presence, heartbeatAt, activeModules, modules}` 在旁边用 Mono 敲出来，只有变了的模块亮起。
- 没变化时每 90 秒寄一个空信封，画成一次呼吸。
- 切应用先等 400 ms 落定，画一把小尺子。
- 窗口标题先过 Jev：几道问题的条纹同时转，同一刻一起给出概率条。放行的进信封，拿不准的弹给主人。
- 图片：像素压成一条哈希 `sha256….png`，直接落进 R2 的抽屉。信封里只剩一个文件名。

### 02 门禁与分拣（FACTS §2）

图版翻成**纸面**，墨线加橙色印章。

1. **一墙八扇门**：每封上报带着自己的钥匙卡，Emby 的钥匙去开 mac 的门，被 403 印章盖回去。
2. **一张检查单**，按代码顺序逐项打勾：
   1. POST
   2. 来源认识
   3. Access 凭证（RS256，aud / iss / exp）
   4. 秤上称重：不超过 4 MiB
   5. 是 JSON
   6. prepare
   
   不通过的项各飞一枚章：不是 POST 盖 405，来源不认识盖 404，凭证盖 401 / 403，超重和不是 JSON 盖 400，prepare 失败盖 400（状态核心还没准备好时盖 503）。OTLP 那一路另有一枚 415，这里不画。
3. **分拣台**：信封拆开，内容分进四根气动管：实时、可滞后、归档、凭据。
   - 服务器的信封整封不进状态核心：它的管子分叉到可滞后格子和档案架。冷面脚注：「服务器：整封不进屋。」
4. **202 这枚章要等三盏灯**：DO、LAG、凭据。D1 那盏不等，它在后台慢慢亮。
5. 旁注：改检查单只需要重新发布入口，屋里的灯不闪，连接不断。

### 03 一间屋子的账房（FACTS §3）

样章第一版用满屏铜版画排线的 3D 屋子，用户反馈「完全看不清想表达什么」，已整段重做。现在的做法：**3D 只负责空间，含义交给和代码一一对应的纸面文档**（第 02 章检查单的经验）。

- **屋外**：夜里只有一间屋子，窗里透出灯光（`idFromName("global")`，唯一的状态 DO）。信封在门外排成一队。
- **掀顶**：第 2 小节强拍上屋顶掀走、前墙落下，变成剖面模型：暗底、骨白轮廓、墙体切口打斜线。
- **账本**：信封一拍一封进门、上桌。右边一张纸质账本，每拍写一行「来源 · 记下什么」并打勾（SQLite：entries / fields / samples / metadata）。
- **要做的事**：一次切应用落账后，写出一张清单：「广播推送」「通知 Vercel 失效标签（布局变了才有）」。清单从右墙的缝递出去，交给门外的 StateCore 岗亭。
- **门外照单办**：同一拍出发两件事：
  - LivePushRoom（另一个单例 DO）的天线在地面荡开橙色环，送往所有开着的页面。
  - 一张回执飞回入口，旁注「入口等齐三盏灯才盖 202」。
  
  中间标「并行」。
- **纯心跳**：记下存活时间和两条 pulse 观测；清单是空的，天线不动（Clawd 在桌角：「记一笔就好，别吵醒大家」）。只有在线状态翻转才广播 presence、失效 3 个标签。
- **拉远**：LAG 墙、D1 三排档案架、凭据抽屉柜按拍从地里升起。配一张「四个库」对照表：实时 / 可滞后 / 历史 / 凭据 → 落在哪 → 推不推送。另注「pulse 时间线在屋里只放 7 天」。

### 04 活字印版（FACTS §4）

**纸面印刷**：主页是 25 块印版拼成的一页，每张卡一块，各自缓存。

- 访客来了，从存货里递出一张印好的页。
- 一个标签失效：只有那一块印版重铸，旧页照发，新页在后台印。
- 7 块没挂标签的印版，只看 600 秒的定时器。
- 某个来源 5xx：那块印版不动，继续用上一份。

### 05 电报线（FACTS §5）

**暗底示波器**，横轴是毫秒：

1. HTML 还在解析，head 里的小脚本就开始接电报线 `/ws?visible=1`，收到的电报先放进一只小托盘。
2. 等页面 hydrate 完，`useLiveEvents` 接过线，托盘里的电报按顺序重放。时间轴只画先后，不标毫秒数（没重测过）。
3. 一条推送到：写进 SWR，卡片当场翻面。
4. 一个慢回来的旧轮询带着更早的时间戳，被弹开。
5. 播放进度条按「位置 + (现在 − 观测时间)」自己往前走，歌词占位逐字亮。
6. **两只钟**：卡片的在线点到了截止时间、源站什么也没说，它照样自己熄灭，因为浏览器按自己的钟判断。
7. 同一根线数两种人：开着的页面，和正在看的页面。切后台只发一个 `hidden`，线不断。这里第一次出现 live 绿。
8. 一张「预期到货表」：可滞后卡在 `updatedAt + 节奏 + 15 秒` 时才去取；推送连着时，在听列表、在看、在玩、奖杯这几张退成 5 分钟兜底。

### 06 两条线路（FACTS §6）

**纸面地铁图**：

- 两条线：lyjw.me（Vercel）和 lyjw131.com（阿里云 ESA）。ESA 站缓存 5 分钟；过期后先给旧页，后台回源。
- 图片是图书馆索书号：`/img/<哈希>`。内容变了名字就变，永远不用刷新。
- **发版接力**，一站一站亮起来：
  1. Vercel 部署成功
  2. Actions 刷新 ESA 并预热
  3. 两个域名的 `/api/version` 都答出新版
  4. 入口收到 site-deployed
  5. 广播 version
  6. 所有开着的页面顶上弹出 UPDATE 卡

### 07 节拍器（FACTS §7）

**纸面上三台节拍器**：PlayStation、编码账号限额、服务器。

- 人数从同一个房间读出：有人正看 → 快；只开在后台 → 中；没人 → 慢。
  - PS：55 秒 / 115 秒 / 29.5 分钟
  - 限额：5 / 10 / 60 分钟
- 入夜后访客走光：
  - PS 慢到 29.5 分钟。
  - 限额那台打 12 个 5 分钟的盹。
  - 只有服务器那台固定每 60 秒敲一下。它是对照：闲时每分钟问一次人数，本身就不比直接推一次省，所以它不问。
- **电源门**：客厅的 PS5 开机，节拍器在下一响就跳回快档；PS5 关机时，不管有没有人都停在 30 分钟档。
- 人数问不到就当 0：只会变慢，不会变快。
- 配乐在这一章真的换档：半速、全速、再慢下来。

### 08 心电图与地层（FACTS §3、§8）

**暗底**，两个方向相反的信号：

- Sentry 每分钟来敲一次门（HEAD `/api/version`）。
- Worker 每 5 分钟去报到。冷面脚注：「报到只证明 cron 跑完了。」

collector 每 5 分钟取回结果，LYJWPAGE 卡上 30 天一天一格，今天那一格亮一下（live 绿第二次、也是最后一次出现）。

然后镜头往下沉，进入**地层**：

- pulse 每分钟归档进 D1。
- Coding 每 15 分钟一窗，交给 Jev 打分。全是零的窗不问 Jev，直接记最低档。
- 地层一层层长厚，长期保存。

Clawd 收尾：「线上出错时，我先来这儿查证据。」

### 09 一首歌的旅程（FACTS 全篇）

一镜到底：Mac 上切歌 → 钥匙开门 → 称重 → 分拣 → 屋里排队 → 清单 → 广播和 202 同时发出 → 电报线 → 卡片翻面。信封经过哪一章的地方，那一章的画法就闪回一下。延迟计数只有重测过才出现。

片尾：谢谢观看 · 讲解 Claude Opus 5.5 · lyjw.me。画面收回终端，停在第一帧，首尾相接可以循环。

## 配乐（一种）

- **风格**：温暖的极简电子。
  - 侧链呼吸的 pad、FM 铃音和拨弦、低音、干净的鼓组，带一点磁带饱和。
  - 一段四音的**信封主题**：信封每次出场都用它，每章换一件乐器来唱。
- **每章的配器跟着画法走**：

| 章 | 配器 |
|---|---|
| 02 | 打字机和印章当打击乐 |
| 03 | 十六分音符的钟摆声，对应一条队列 |
| 04 | 印刷机的重拍 |
| 05 | 电报点划藏进踩镲 |
| 06 | 转调、铺开声场 |
| 07 | 节拍器真的换速 |
| 08 | 底鼓就是心跳 |
| 09 | 全主题 |

- **节拍直接从乐谱出**：引擎读的是乐谱给的鼓点和包络时间表，不做音频分析。画面上所有「落在拍上」的动作都查这张表。
- 画面音效沿用上一版的做法（从画面生成音效轨，再和配乐混音、响度校准），只配一种音色。

## 技术路线（样章实测后定）

- **位置**：仍在 `docs/explainer/`，由 `scripts/build-explainer.mjs` 按内容哈希发布，脚本和音频经 `window.__assets` 查名字。
- **引擎**：换成 WebGL2。基础件有：全屏着色器通道、Canvas2D 文字层转纹理、GPU 线段批、线性 HDR 加后期（只让 signal 起 bloom，加光晕、胶片颗粒、暗角，纸面图版叠纸纹）。
