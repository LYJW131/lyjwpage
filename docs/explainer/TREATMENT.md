# lyjw.me 运行原理 · 画面升级本子（v2：全片 2D）

> 类型：reference

这份本子定下一版讲解动画的概念、风格、分镜结构和技术路线，先审本子再写代码。事实一律出自 [FACTS.md](FACTS.md)，本子里提到的机制都能在那里找到出处。章节表、逐段画面和逐句旁白在 [SCRIPT.md](SCRIPT.md)，写章的契约在 [v2/CONVENTIONS.md](v2/CONVENTIONS.md)。

lyjw 看过第 02、03 章样章后拍板**全篇统一 2D**：第 02 章的纸面检查单是全片的标杆，第 03 章是暗底平面图加白卡详图（见下文 03 节）。

参考：[mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)。借它的方法：

- 画面是时间的纯函数。
- 本子先行。
- 一条贯穿全片的母题。
- 每章一种视觉语言，但共用同一套调色板和字体。
- 硬切落在强拍上。
- 字就是画面的一部分，不是贴在上面的字幕。

不借它的：歌词对齐流程（我们的配乐是自己合成的，节拍天生已知）；离线渲 mp4（交付仍是可播放的 HTML）。

## 一句话概念

**一封信封的旅程，画成一本工程图册。** 代码里本来就管两样东西叫「信封」：上报器发出的遥测，和首屏里每张卡片的数据。片子跟着一封信封（Mac 上的一次换歌），从它在 Mac 上被写出来，一路走到访客屏幕上那张卡片翻面。每一章是图册里的一页「图版」，各用一种工具和画法：

- 野外仪器的专利图
- 公文和印章
- 只有一间屋子的账房
- 活字印版
- 电报示波器
- 心电图和地层
- 对话卡和分拣台（对话）
- 插孔看板和分支图（站是怎么被造出来的）
- 流水线总图（发布）

信封走到卡片翻面之后，后几章讲同一个站的另外几面：首页上的对话、lyjw 的一句话怎么变成合进 main 的提交、推到 main 之后怎么发布。整本图册共用同一张纸、同一种墨、同一种橙色。

## 母题

1. **信封（贯穿全片的「火花」）**：一个 Claude 橙的亮点，拖着一根发丝线。镜头推近时，它是一个极小的信封（矩形加 V 形封舌）。它的一生：
   - 在 Mac 上被写出来
   - 在入口被拆开、分成四路
   - 在账房里排队
   - 被印进首屏
   - 顺着电报线送到浏览器
   - 最后在回顾章一口气走完全程
2. **四个库，四种符号**，全片一致（共用 `K.glyph`，第 02 章的管子底下、第 03 章的对照表都是它）：
   - 实时层：DO，一间屋子
   - 可滞后层：KV `LAG`，一墙带时间签的格子
   - 历史：D1，一条望不到头的档案架，长期保存
   - 凭据：KV `CREDENTIALS`，一只带锁的小抽屉

   观众看到符号就知道数据落在哪一层。
3. **钥匙与门**：每把钥匙只开权限表上写着的门（Home Assistant 那一把只开 /homepod，/playstation 只认 PlayStation 容器自己那把）。第 02 章立起来，回顾章再出现一次。
4. **两只钟**：服务器的钟，和访客浏览器自己的钟。在线判断、可滞后卡取数、播放进度，都是「浏览器按自己的钟算」。这个母题在第 05 章立起来。
5. **Clawd**：像素螃蟹，片子的脸，也是 Claude 自己。第 00 章它说「lyjw 出主意，我们几个 Claude 动手」，第 08 章兑现这句话。出场规则见「已定」。

## 调色板

取自站点 `src/app/styles/theme.css` 的 token，实现时按 oklch 换算成线性色：

| 名 | 来源 token | 用途 |
|---|---|---|
| ink | 暗色 `--background` oklch(0.15 0.008 85) | 暗图版底色 |
| ink2 | 暗色 `--surface` oklch(0.185 0.008 85) | 面板、暗底上的实心物件 |
| paper | 亮色 `--background` oklch(0.94 0.007 92) | 纸面图版底色、暗底上的白卡 |
| bone | 暗色 `--foreground` oklch(0.93 0.012 90) | 暗底上的字与线 |
| graphite / ash | `--muted-foreground` 两档 | 次要线、注记（纸上用 graphite，暗底用 ash） |
| **signal** | `--claude` oklch(0.672 0.131 38.8)；暗底用 oklch(0.74 0.115 39) | 信封、强调、橙色印章。全片唯一发光的颜色 |
| ember | signal 提亮 | 信封亮核 |
| **live**（稀有） | 暗色 `--live` oklch(0.76 0.16 148)；纸面用亮色 oklch(0.65 0.17 145)，第 06 章水墨版用石绿 | 只属于「在线」这一个含义：第 05 章在线人数、第 06 章的可用格。别处不用 |

规则：

- 暗图版和纸面图版交替，形成明暗节奏。橙色在两种底上都还是橙色。
- 只有 signal / ember 可以超过发光阈值，bone 字不发光。
- 不用别的色相。站点卡片里本来的颜色（活动圆环三色、各品牌色）在片中都画成 signal / bone。

## 字体

| 字体 | 声部 |
|---|---|
| Geist（Medium / SemiBold / Bold） | 标题、英文旁白 |
| Geist Mono | 机器的声音：端点、状态码、JSON、计时、注记 |
| Geist Pixel | Clawd、终端、章节号 |
| PingFang SC（系统字，回退 Noto Sans SC） | 中文旁白与标注 |

排版：

- 瑞士网格、不对称构图、大量留白、发丝细线。大字旁边配小号 Mono 注记。
- 不描边、不加光晕。
- **手机可读性下限**：舞台按 1920×1080 逻辑像素排版，375px 宽的手机上会缩到约 0.2 倍。
  - 旁白不小于 56 逻辑 px（手机上约 11px）。
  - 要读的标注不小于 28 px。镜头拉远时按缩放折算：缩放 0.66 下，世界坐标里的字要写到 46 px 以上。
  - 更小的字只能当纹理，不能承载信息。

## 语气与禁区

- 一直有东西在动，大变化落在拍子上：强拍硬切，鼓点上盖章、落卡、翻面。强缓动，停住后再猛地弹出，不做飘来飘去的屏保式运动。
- 精确而不花哨：发丝线、高反差字、克制的颜色。冷面幽默：一本正经的脚注、印章、状态码。
- 不做 AI 味：
  - 不要紫青霓虹、发光大脑、代码雨、粒子星云、镜头光晕堆叠。
  - 不要云朵图标加服务器机柜这类库存图示。
  - 厂商只以 Mono 字出现名字，不画厂商 logo，不模仿别家产品界面。站点自己的主页可以画。

**不上画面**（沿用上一版的口径）：

- 窗口标题的隐私判断：只说 Jev 参与、拿不准交 lyjw、放行才进信封。不写判据、阈值、例子。示意概率条不和出路对应。
- 站点自检：不出 Cloudflare 账号 ID、真实报错标题、可用率数字。令牌不上画面；它的权限范围未核（FACTS §8），不说「只读」。
- 不出真实密钥和 token 的 client id，钥匙只画成「mac 的钥匙」。
- 歌词用占位。
- 延迟数字要重测过才能出现；上一版的 8 月实测作废。

## 2D 画法总则

全片每一页都是一张平面图版，下面这些做法各章通用（第 02、03 章已经验证过）：

- **图版底**：纸面（`K.PLATE.paper`：纸纹、纤维、墨点、40 / 200 的图纸网格）和暗底（`K.PLATE.ink`：墨色底、很淡的云纹、骨白网格）两种，都是按世界坐标画的全屏 2D 着色器，镜头动时纸纹跟着纸走。
- **镜头**：只有平移、缩放、旋转。一章一张大图纸，分几个机位；镜头在强拍上甩到下一个机位（约 0.2–0.3 小节，`E.io`），停住时慢慢推 1–3%。甩镜头带运动模糊，冲进、拉出带径向模糊，都是按镜头速度算的后期。
- **物件**：一律正视或俯视（专利图、平面图、立面图），不画透视。门开是门扇平着变窄；卡片翻面是纵向压扁再弹开；「从地里升起」是往上平移、裁到地平线以上。
- **详图**：暗底图版上要读的文字放进白卡（`K.sheet`，按纸片模式合成，和纸面图版是同一张纸）。白卡用虚线圈加虚线引到画面里的实物上，这是工程图的「详图」画法。纸面图版上直接写。
- **旁白**：大字（≥ 56 px），逐字亮起，排在每个机位留好的位置上（多在左下），和图一起构图。
- **打勾、印章、灯**：清单按拍打勾（`K.checkbox`），印章落在强拍上（`stamp` 合成模式），「等齐几样才放行」画成一排灯。
- **发光**：只有 signal 色的东西进发光层（信封亮核、灯、广播的环），其余都不发光。

4. 镜头顺着橙点身后那根线往回拉，拉出总览图：采集 → 中枢 → 展示。中枢分成四块（上报入口 ingress、状态核心 core、采集 collector、对话与构建 ai），下面挂着四个库的符号。

### 01 野外观测站（FACTS §1）

镜头横移，经过六件仪器，每件画成暗底上的专利图：

- 笔记本（Mac）
- 手机（iPhone，由 HealthKit 唤醒来报圆环和训练）
- 家里：HomePod（经 Home Assistant），旁边是 n100 上的 PlayStation 容器：在同一个局域网里探测主机醒没醒，拿本机的 PSN 登录态问 Sony，用自己的钥匙寄到站点（三样凭据分开画，见 FACTS §1）
- NAS 机箱（Emby）
- 东京的机柜，一台主机上的几个容器（服务器、编码账号、Quest 在玩什么），各用各的钥匙
- 云端的一小段遥测（Claude Code OTLP）

最后是一只**表盘**：collector，每分钟一响，每个任务一根指针，各走各的节奏。表盘后面接一张 FIG. 7A「没人上报的播放」：iPhone 等别的设备上放的 Apple Music 没有上报器，采集 Worker 去拉 Apple 的最近播放（列表一变就每 15 秒拉），新歌开播几秒就排到最前；站点这边把相邻两次拉取之间的窗口按时长接成一串、求交，推出每首的开播和误差，页面上画成 Likely Playing 加虚线框里的误差，以及 Pulse 上的斜线段。

Mac 这一站展开讲：

- 信封 `{version:4, presence, heartbeatAt, activeModules, modules}` 在旁边用 Mono 敲出来，只有变了的模块亮起。
- 没变化时每 90 秒寄一个空信封，画成一次呼吸。
- 切应用默认先等 400 ms 落定，画一把小尺子。
- 窗口标题先过 Jev：几道问题的条纹同时转，同一刻一起给出概率条。放行的进信封，拿不准的弹给 lyjw。
- 图片：像素压成一条哈希 `sha256….png`，直接落进 R2 的抽屉。信封里只剩对象键。

结尾镜头甩回 Mac：Clawd 落到那封换歌的信封旁，气泡「我跟着这一封走」，跳上信封一起骑出画面右缘；第 02 章它骑着火花从左边进门。

**2D 画法**：一长条暗底图纸，镜头只做横移（每件仪器一个机位，强拍上甩，甩的那一下配一口风）。每个机位留够读图的时间：动作做完后至少停一小节，每一站配一句讲机制的旁白。仪器是正视专利图：骨白发丝线、编号引线（FIG. 1…）、剖切斜线。信封 JSON 放进白卡详图逐字敲出。呼吸是一个圆环缩放；400 ms 是一把平面刻度尺；Jev 的几道问题是并排横条同时走；表盘是正视钟面。

### 02 门禁与分拣（FACTS §2）

图版翻成**纸面**，墨线加橙色印章，是全片的标杆。这一章讲到「实时那一半经 Service Binding 交给 StateCore，回执回来」为止，屋里的事留给第 03 章。

1. **一墙九扇门**：一个来源一扇门（`INGEST_SOURCES` 加 OTLP 那一路）。每个上报方一把钥匙，只开权限表上写着的门；Emby 的钥匙去开 mac 的门，被 403 印章盖回去。
2. **一张检查单**，按代码顺序逐项打勾：
   1. POST
   2. 来源认识
   3. Access 凭证（RS256，aud / iss / exp）
   4. 秤上称重：不超过 4 MiB
   5. 是 JSON
   6. prepare：校验并整理成命令

   不通过的项各飞一枚章：不是 POST 盖 405，来源不认识盖 404，凭证盖 401 / 403（验不了时 503），超重和不是 JSON 盖 400，prepare 失败盖 400（状态核心还没准备好时盖 503）。OTLP 那一路另有一枚 415，这里不画。
3. **分拣台**：prepare 出的命令按数据层分进四根气动管：实时、可滞后、归档、凭据。三根由入口自己写，只有实时那根交给状态核心。
   - 服务器的信封整封不进状态核心：它的管子分叉到可滞后格子和档案架。
4. **跨 Worker 的一跳**：两个 Worker 之间一堵剖切墙，实时那根管子从墙上的口（Service Binding `CORE`）穿过去，进 StateCore（RPC 入口），再进 StateHub（唯一的状态 DO，画成「实时」那间屋子）；回执 `{ ready, ok, data }` 顺原路回来。内部调用不走公网、不带凭据，鉴权只在边界做一次；改校验只发布入口，DO 不重启。
5. **202 这枚章要等三盏灯**：状态核心回执、LAG、凭据，依次 `await`。D1 那一路 `waitUntil`，不等，在 202 之后才远远亮起。失败时：没准备好回 503，稍后重发；任一步抛错回 400，上报器整封重发，各路按自然键写，重发不重复。

Clawd 骑着火花进门，落到标题线上说一句；Emby 的钥匙被 403 盖回去时它当拍一缩，之后跳出画面。

**2D 画法**：一张 3840×3240 的纸面图纸，两列三行（门墙、检查单、分拣台、跨 Worker 的一跳、三盏灯，左下那格是图签），镜头在强拍上甩到下一格，最后拉远看整张图纸，再冲进「状态核心已提交」那盏灯，整屏化成橙色落黑，接第 03 章。门开是门扇平着变窄；墙是平面图的剖切墙，管子穿墙处画一对法兰，不做透视。

### 05 电报线（FACTS §5）

**暗底示波器**，横轴是时间：

1. HTML 还在解析，head 里的小脚本就开始接电报线 `/ws?visible=1`，收到的电报先放进一只小托盘。
2. 等页面 hydrate 完，`useLiveEvents` 接过线，托盘里的电报按顺序重放。时间轴只画先后，不标毫秒数（没重测过）。
3. 一条推送到：写进 SWR，卡片当场翻面。
4. 一个慢回来的旧轮询带着更早的时间戳，被弹开。
5. 播放进度条按「位置 + (现在 − 观测时间)」自己往前走，歌词占位逐字亮。
6. **两只钟**：卡片的在线点到了截止时间、源站什么也没说，它照样自己熄灭，因为浏览器按自己的钟判断。
7. 同一根线数两种人：开着的页面，和正在看的页面。切后台只发一个 `hidden`，线不断。这里第一次出现 live 绿。
8. 一张「预期到货表」：可滞后卡在 `updatedAt + 节奏 + 15 秒` 时才去取；推送连着时，在听列表、在看、在玩、奖杯这几张退成 5 分钟兜底。

电报线一接上，戴耳机的报务员 Clawd 落到线头的电键旁，按三下电键，三封电报掉进托盘；hydrate 之后它左右看一眼，镜头甩走就不再画它。

**2D 画法**：暗底，一条 signal 色的示波曲线横贯画面（发光层）。小托盘是一叠小卡片，hydrate 是一道竖刻线；卡片翻面同第 00 章。旧轮询是一只小信封撞上时间戳闸门弹开。进度公式用 Mono 写在进度条旁边。两只钟是两个正视钟面（服务器、访客浏览器）。预期到货表是一张白卡表格。

### 06 心电图与地层（FACTS §3、§8）

**宣纸水墨**，两个方向相反的信号：

- 采集 Worker 每分钟来敲一次门（GET `/api/version`）。
- Worker 每 5 分钟去报到，自己记一笔心跳。冷面脚注：「报到只证明 cron 跑完了。」

两边都记进 D1 的 `health_buckets`；collector 每 5 分钟汇总一次，经可滞后层上 LYJWPAGE 卡，30 天一天一格，今天那一格亮一下（live 绿第二次、也是最后一次出现，画成石绿）。

然后镜头往下沉，进入**地层**：

- pulse 每 5 分钟归档进 D1。
- Coding 每 15 分钟一窗，交给 Clef 打分。全是零的窗不问 Clef，直接记最低档。打分只在屋里（StateHub）放 7 天，不进 D1。
- core 的 cron 每 5 分钟一轮，报到的同一轮往地层右沿压进一薄片，长期保存。

Clawd 从地层上沿冒出来收尾：「线上出错时，我先去 Workers Issues 查证据。」

**2D 画法**：同一部片里这一章换成水墨，像原片一章换一种画风。两个信号画在同一条心电图横线上，这条线是一笔墨：横走时粗、竖走时细，收笔带飞白；向内的尖峰是采集 Worker 敲门，向外的是 Worker 报到，线上那只框是记账的 `health_buckets`，四笔勾成。钟面是一笔圆相。30 天格子的 LYJWPAGE 卡裱成挂轴，角上一方「墨」字小印。「下沉」是镜头纵向平移，地层是一层层水平墨晕（墨分五色：焦、浓、重、淡、清轮着铺，上沿是一道湿边），右沿是此刻，报到那一拍压进一薄片，越往左越早。Coding 的窗是横向一格一格，全零的格直接落最低档；Clef 打出的档画成窗里的一根横线，窗角盖一方小朱印，旁注它不进 D1。旁白是毛笔楷，后面垫一块边缘渐淡的宣纸，压在地层上也读得清。

### 07 对话（FACTS §9）

**纸面**，接第 06 章的宣纸。不在一首歌的链路上：首页的 Talk to God 对话怎么花钱、读什么、怎么把访客的改站想法变成一个草稿 PR。

- **开场**：第 06 章的心电图横线硬切成纸面上一条墨线，收成对话卡的输入框，笔尖成了光标；访客打出第一句，卡片先回隐私说明，接受之后才验人、发请求。
- **过闸**：验人（通行证或 Turnstile）、ChatQuota 三道额度，一项一勾；被挡下的一条盖 429，到此为止，不调 Clef。
- **分拣**：Clef 把消息分给三档（Fable · God、Sonnet · Prophet、Haiku · Small Fry），选中的那档满了就往下降一档；refuse 不调模型。
- **工具**：模型经 `SITE_TOOLS` 查站点，`PUBLIC_STATUS` 读的是浏览器看到的同一份公开模型；同一套工具挂在 `/mcp` 上给外部 AI 客户端。回到卡片：回复带着在听卡，盖一枚章。
- **设计与构建**：访客想改站，Sonnet 开设计会话，Opus 在只读沙盒里克隆仓库、出题、出计划；Start build 之前先看 GitHub 授权说明；Worker 把计划提交到构建分支、开草稿 PR，GitHub Actions 里的 Claude 写代码，改动回传 Worker 校验后提交。合不合并由 lyjw 决定，镜头落回 main 线，交给第 08 章。

**2D 画法**：对话卡照站点原样画成线框（标题、气泡、输入框）；闸门、额度、档位都是正视的方框、勾和格子；沙盒是一圈虚线框；分支是从 HEAD 弯出去的一根线。发光的只有消息的火花和灯。设计会话那张 Opus 卡上冒出一只戴安全帽的 Clawd（Architect），只在卡里，不压卡上的字。

### 08 一句话之后（FACTS §11）

**暗底**，接第 07 章落回的 main 线。不在一首歌的链路上：lyjw 在项目聊天说一句，这句话怎么变成合进 main 的提交。这一章的主角是 Clawd，一只 Clawd 就是一个 Claude。例子是真的 PR #308（PageSpeed 两行老显示「—」），提交哈希、PR 标题和合并卡照 GitHub 原文。

- **开场**：main 线上的旧提交一颗颗冒出小 Clawd，线下注 `Co-Authored-By: Claude`；向导 Clawd 跳上 HEAD，接第 00 章那句「我们几个 Claude 动手」。
- **看板**：项目聊天画成一面插孔板，旁边一张「项目记忆」白卡写三条规矩；戴耳机的协调 Claude 接住 lyjw 滑进来的纸条，把一根线插进空插孔，插孔标 #308。
- **线程**：#308 那根从 HEAD 弯出分支，线程 Clawd 落第一个提交，先过本地门禁，按改动挑着跑。
- **PR 与评审**：CI 打勾；机器评审一张张滑进来，改了的打勾，回理由的往下落；注「Codex 最多三轮」。
- **验证**：拿放大镜的 Haiku Clawd 按提交跑检查，签一张验证回执（完整 SHA、等级、证据），旁边一列等级梯子；`verify-receipt.ts check` 回 `exact`、`pass`。
- **三道闸**：文档、#308、界面各推一张牌到自己那一档的闸前；判定员 Clawd 先给 #308 盖 FAIL，补一个提交后盖 PASS；界面那道等「lyjw 点头」。
- **合并**：三根分支依次弯回 main，合并提交卡列出各提交主题和 `Co-Authored-By`，连到 lyjw.me 首页的 Commits 卡，头像那一格跳出 Clawd。
- **夜班**：一条 00:00–09:00 的时间轴，游标走过时每个定时任务冒出一只 Clawd：盯防采集、记忆镜像、代码审查、提炼 skill、读 Anthropic 动态、晨报。
- **收尾**：线程 Clawd 站在新的 HEAD 上举牌「等 lyjw 验收」，跳出画面，最后一帧只剩 main 线。

**2D 画法**：一张横向长图纸，main 线贯穿下方，三根分支从 HEAD 弯出去、往右依次经过线程、PR、验证、合并闸门，最后弯回 main；看板和夜班时间轴在上方。卡片都是白卡详图；闸门是正视的方框和门扇。发光的只有 HEAD、灯和亮起的一行。Clawd 按戏份戴道具（耳机、放大镜、牌子），不画厂商 logo，评审机器人只写名字。

### 09 发布（FACTS §10）

**纸面**，接第 08 章（硬切纸面）。画的是合进 main 之后的事：几条流水线怎么各自决定跑不跑、各自构建发布，部署成功之后怎么刷新 ESA、通知开着的页面。例子是第 08 章那个 PR #308 的真实合并 `a451a72..cf92f7c`。

一张流水线总图，工程图的画法，不另起比喻：

- **一根主轴贯穿全章**，就是屏幕 y 540 那条线：第 08 章收在 main 线上，提交圆点在 x 50…1250，这次的合并提交 `cf92f7c` 是 x 1350 的 HEAD；site Worker 那条流水线顺着主轴往右，落地时接上源站，再往右就是 lyjw.me 线。
- **其余流水线从这次的提交散开**，按平台分组：GitHub Actions 在上，Workers Builds 在下。每条一个闸门：放行的打勾、写理由（改到的路径，或每次都跑）；设了监视路径而这次没改到的划一道，闸门后变虚线、灯是空的。走过的一段变橙，一步一个圆点，做完亮灯（第 02 章三盏灯的画法）。各条在这一镜里自己跑完，灯按 `cf92f7c` 上那几项检查的真实完成先后从下往上亮。
- **落地**回到主轴，画源站、ESA 和 lyjw.me、lyjw131.com 两条线，只画线和站，不讲缓存怎么过期：源站亮，ESA 手上的首页划掉、重新取一份，两个终点站先后打勾；再往右是上报入口、StateCore、推送房间和两个浏览器窗口，前台弹出 UPDATE 卡，后台标签页自己刷新。
- **收尾**拉远看整张图纸，再落回主轴，别的都退掉，最后一帧只剩屏幕 y 540 一条墨线，交给回顾章长图版的脊线。

**2D 画法**：只有正视的线、圆点、方框和纸片；闸门是一个方框，打勾或划一道；UPDATE 卡纵向弹出；浏览器窗口是平面线框，后台那扇从上往下换成新的一版。发光的只有火花、灯和广播的环。落地那段一只拿放大镜的小 Clawd 客串合并后的部署核对（`scripts/deploy-check.ts`）：两个域名的 `/api/version` 各打勾时，它跳一下。

### 10 一首歌的旅程（FACTS 全篇）

一镜到底：Mac 上切歌 → 钥匙开门 → 称重 → 分拣 → 屋里排队 → 清单 → 广播和 202 同时发出 → 电报线 → 卡片翻面。信封经过哪一章的地方，那一章的画法就闪回一下。延迟计数只有重测过才出现。Clawd 一路追着信封跑，每到一格换一种待法：骑在信封上过门、过秤，站上实时那根管子，翻墙坐进账房的椅子，骑着推送的亮核出门，跳上缓存卡，最后在页面边上欢呼。

片尾：谢谢观看 · 讲解 Claude Opus 5.5 · lyjw.me。前面几章戴过道具的 Clawd（耳机、安全帽、放大镜、举牌「等 lyjw 验收」）从欢迎框上沿冒出来谢幕，和框里那只一起庆祝，再缩回去。画面收回终端，停在第一帧，首尾相接可以循环。

**2D 画法**：一张横向长图版，把前面各章缩成一格格并排，镜头沿信封的路一路平移，强拍上推近；信封进哪一格，那一格就换回那一章的底（纸面 / 暗底）亮一下。各章的画法要能以函数形式复用（见下文「分章协作」）。

## 配乐（一种）

- **风格**：温暖的极简电子。

| 03 | 十六分音符的钟摆声，对应一条队列；心跳段底鼓变成扑通扑通 |

| 05 | 电报点划藏进踩镲 |
| 06 | 底鼓就是心跳 |

| 08 | 拇指琴在合并那一刻唱主题，夜班里零星弹琶音；每只 Clawd 一跳一声小跳；门禁、检查一项一声叮，回理由的往下一滑；回执和闸门上落印章 |

- **节拍直接从乐谱出**：引擎读的是乐谱给的鼓点和包络时间表（`Score.events`、`Score.env`），不做音频分析。画面上所有「落在拍上」的动作都查这张表或写死在同一套小节里。
- **按章拼装**：每章一份乐谱（`v2/music/ch<NN>.js`，章内小节），`v2/score.js` 只放合成器和共享词汇（和弦、鼓型、贝斯型、琶音型、信封主题、剧情音），按章节表把各章接成整片；还没写谱的章用占位（轻 pad、每拍一声滴答）。写法见 [v2/CONVENTIONS.md](v2/CONVENTIONS.md)「配乐」。
- 画面音效：剧情音（钥匙、印章、打勾、气动管、灯、广播、Clawd 的小跳）直接写进各章乐谱的 `story`，和画面同一张时间表，没有另做音效轨。

## 技术路线

- **位置**：`docs/explainer/v2/`；站点版由 `scripts/build-explainer.mjs` 从这里按内容哈希发布（脚本和音频经 `window.__assets` 查名字），见 [README「站点版」](README.md#站点版)。
- **引擎：保留 v2 自写的 WebGL2 引擎，只当 2D 合成器用。** 决定的理由：第 02 章（标杆）的质感来自纸纹、墨吃进纸、橡皮章空隙这几种逐像素的合成和后期（只让 signal 起泛光、颗粒、暗角、按镜头速度的运动模糊），换成纯 Canvas2D 要么丢掉这些、要么在 CPU 上逐像素重做；而 2D 用法下它已经很轻（实测见下）。
  - 没有光线步进、透视相机，也没有 3D → 屏幕的投影。
  - 镜头：`{x, y, zoom, rot}` 四个数，Canvas2D 图层（`Layer.cam`）和着色器（`uCam`）用同一套；关键帧用 `K.keys`，`K.camera(CAM, b, BAR)` 顺带给出运动模糊和径向模糊。
  - 图版底：`K.PLATE.paper` / `K.PLATE.ink`，`uPlate` 限定网格范围。
  - 合成模式：`normal`、`add`（只给 signal 的发光）、`ink`（纸上吃墨；暗底上的骨白线也用它）、`stamp`（橡皮章）、`paper`（暗底图版上的白卡，颜色乘同一套纸纹）。
  - 图层共用：各章按名字从 `G.layer(name, scale)` 取（`ink`、`paper`、`stamp`、`top`、`emit`@0.5），同一时刻只画一章，所以各章共用一组画布；着色器用 `G.pass(src)` 按源码缓存。
  - 共用件在 `kit.js`：`glyph`（四个库）、`sheet`（白卡）、`checkbox`、`leader`（引线标注）、`pathAt / pathLen / trailOn`、`camera`，以及原有的文字、信封、印章、Clawd、气泡、火花。
- **确定性**：画面只取决于时间 t。随机数一律带种子，逐帧闪烁按帧号算。`?export`、`?t=`、`window.__ready`、`__seek`、`__duration`、`__chapters`、`__BAR` 保持不变。
- **双语**：所有文字在源头按句查表（`I18N.tr(key)`，中英两列）：播放器的字在 `v2/i18n.js`，各章的字在各自文件顶部的 `I18N.add`。时长仍按中文算，两种语言共用一条配乐；英文句子要按画面位置控制长度（多为两行）。
- **性能**（Apple Silicon，无头 Chrome + Metal，`__seek` 含 `gl.finish()`，整帧时间）：
  - 1920×1080：第 02 章中位 2.6 ms、p90 4.2 ms；第 03 章中位 1.8 ms、p90 3.7 ms。
  - 3840×2160（DPR 2 的 1080p 屏）：中位 4–5 ms、p90 7–11 ms；第 03 章拉远后偶有一帧约 68 ms，疑为大白卡的阴影模糊在 4K 下贵，没查。
  - 375 px 宽 × DPR 3（画布 1125×633）：中位不到 1 ms。
  - 真机手机没测。竖屏手机按 16:9 加黑边显示。没有 WebGL2 的浏览器要不要退回 Canvas2D 直出（没有纸纹和后期），没定。
- **播放器**：去掉配乐选择，其余保留（播放 / 暂停、拖动、语言切换、封面、重播、触屏底栏）。
- **自检**：`v2/tools/check.mjs` 中英各把一章逐帧画一遍，报太小的字、缺文字键和报错；`v2/tools/stills.mjs` 按章节小节抽帧（`--lang en` 出英文、`--scale 0.2` 出 375px 手机等效图），无头 Chrome 截画布；不要用浏览器面板截图（面板隐藏时是空帧）。联系表用 ImageMagick `montage` 拼。流程见 CONVENTIONS「自检」。

## 分章协作

1. **共享约定**：写章的契约在 [v2/CONVENTIONS.md](v2/CONVENTIONS.md)，章节表、逐段画面和逐句旁白锁在 [SCRIPT.md](SCRIPT.md)，配乐按章拼装。
2. **按章并行**：每章两个文件，画面 `v2/ch<NN>.js`（文字键写在它顶部）、配乐 `v2/music/ch<NN>.js`，互不改动别人的文件；前后两章的接缝按 CONVENTIONS「交接」对一次。回顾章（第 10 章）复用各章的画法，各章改完再动它。
3. **收尾**：配乐全片通听、预渲整片配乐；中英抽帧、手机检查；独立审查闭环后替换线上。
